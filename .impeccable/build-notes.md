## Sheets
Five sheets in two languages, ten pages. `npm run build` = `vite build` + `node tools/build-sq.mjs`.
- **Structure.** vite.config.js lists every page and runs a small plugin that inlines `<!-- @include x.html -->` from partials/ (head, defs, chrome = toolbar + pill + tab bar, dateline, foot, end = index + tiles + canvas + script). One main.js boots every sheet; each module does nothing where its elements are absent. The stage builds the 3D band and the ink fluid only where a band exists.
- **Addresses.** src/routes.js holds each sheet's English and Albanian address. Links carry `data-route` (and `data-hash` for a part of the front page) and are painted for the current language; a link to a part of the sheet you are on scrolls instead of reloading. The language switch re-sets the sheet in place under the tiles and moves the address to its counterpart (history.replaceState, built site only). A saved choice wins; the browser's language decides only on the front page's plain address (x-default).
- **Albanian pages.** tools/build-sq.mjs reads each built English page and writes its /sq/ twin: every data-i18n / data-i18n-list / data-i18n-attr text, the proof notes and the verse are replaced from STRINGS.sq, links marked data-route point at the Albanian sheets, and both twins get canonical, hreflang (en, sq, x-default) and og:locale. Without SITE_URL the links are root-relative and there is no sitemap: set SITE_URL for the launch build.
- **Case plates.** tools/shoot-work.mjs captures the live sites (desktop 1440x900, phone 390 at 2x), one fresh browser context per shot (a notice declined on one shot once hid the next shot's welcome card), declines their non-essential cookies, and places every callout from the page itself. It measures the detail's box (the control it sits in, a small chip around it, or the ink of its text) and every visible text line, control and picture, then sets the ring just outside the detail, on the side facing the key, at the height where a straight rule to the plate's edge crosses no word. Rules may graze leading and button padding, keep 18px of the shot apart (about 11px on the page) and stay in key order; where nothing beside a detail is clear the ring is pinned on its edge. Both sides are written to src/data/plates.json (`r`, `l`: `[x, y, dx, dy]`, the ring's centre and the way out from its detail), in key order: the finder list follows the `<li>`s, nothing is sorted. Up to 1100px the letters are pinned on the plate instead (folio.js), each stepped out from its detail by the size the pin has beyond the ring at that scale, so a desktop shot on a phone keeps its details uncovered. `--debug <dir>` saves each shot with the boxes, rings and rules drawn over it. Traps met: text that ignores the pointer (Elixir's notice bar) falls through `elementFromPoint`, so it is made hit-testable for the test; text inside faded containers (closed tooltips) is skipped; a site's CSP blocks the inline-styled debug overlay (the tool bypasses CSP in debug runs only), and an open `<dialog>` sits above any z-index (the overlay goes inside it).

## Performance
Measure on the production build (`npm run build`, launch entry "stefano-doko-preview", port 3671): `node tools/profile.mjs [--mobile] [--cpu 4] --label name` scrolls with real wheel events, stirs the band, hovers a plate, and records frame intervals and long animation frames. `tools/trace.mjs` (Chrome trace of a scroll stretch) and `tools/cpu.mjs` (CPU profile) go deeper. Runs are saved in `.impeccable/perf/`.
- Before (`before-desktop.json`): 16 long frames (about 1 s in total); the first 2000px ran at p95 50ms with frames up to 150ms; the case sheets ran at p50 33ms (30 fps).
- After (`ship-desktop.json`, `ship-mobile-cpu4.json`): p95 16.8ms in every stretch, 0 long frames on desktop; phone at 390px, DPR 2, CPU slowed 4x: p95 at most 17.4ms, 1 long frame.
- The 50ms frame at the red EXTRA sheet was first thought to be raster of the red layer and left; it is fixed now, see "Red sheet".
What fixed it, in order of weight:
1. The paper textures were megabyte `data:` URLs held in custom properties (--grain, --mottle, --speckle); every style recalc re-parsed them. paper.js now hands them over as `blob:` URLs.
2. One read phase, then one write phase per tick (main.js: editionMeasure, nav.measure, measureInk, stage.measure, then the writes), so the page lays out once per frame instead of being forced to many times.
3. Styles written only when their value changes (toolbar pill/read line/aria-current, case leaders, labels, facts, veil).
4. Composited motion: the ink reveal is a sliding window of two counter-translated layers (no per-frame clip-path); the case veil is its own element animating opacity (was an inherited custom property); the red sheet's slit is a one-shot CSS transition when it enters (was scrubbed); the fan's transitions only run once it is dealt.
5. WebGL: the band's static meshes merged by material (about 370 draw calls to 73), the band re-cut at 30 fps unless the pointer works it, nothing redrawn when nothing changed (scroll, stir, plates, brayer, forced on resize/refit/lang/proof), shader programs compiled up front against the render targets they are used with, plate textures uploaded in idle time, DPR capped at 1.5 on desktop, fluid pressure solve 16 to 10 iterations.

### Red sheet
`node tools/redsheet.mjs [--at selector] [--mobile] [--cpu 4] [--w 1920 --h 960] [--runs 2] [--css "..."] [--profile DIR] [--invalidations]` walks the page down to just above a part of it (the red sheet by default), then records its first sight: frame intervals, every GPU shader compile with the Skia op that asked for it and the scroll position, the longest GPU tasks, main-thread paint/layerize totals, and (with `--invalidations`) which elements repaint and why. Each run is a first visit (empty shader cache) unless `--profile` keeps a profile.
- Cause: not raster. Chrome's GPU process compiled Skia shader programs that nothing earlier on the page had needed (28 to 33ms each, on the GPU main thread, so the frame waits): 8 to 9 compiles, 114 to 151ms, one 50ms frame as the sheet's top entered prepaint at 1920x960.
- Who asked: the About verse's two inline cuts, opened by an animated `clip-path: inset(... round 6px)` (a rounded clip is a program variant no other element uses); the EXTRA stamp, an exact circle (`border-radius: 50%`) with inset rings and a soft shadow (circle-only blur and ring programs); and what was left only compiled with the stamp and the outlined EXTRA head both present (hiding either removed it; no single part of the head was the trigger).
- Fixes: the cuts open by transform and opacity on their own layer (scaleY 0.12 to 1); the stamp's radius is 99px (reads round, draws as a rounded rectangle) and it has its own layer; and a copy of the red sheet is drawn once under the intro and dropped before the stamp opens (`warmExtra()` in extra.js, `intro.covering()` / `intro.onOpen()`), so whatever it compiles, it compiles while the counter hides the page. Not done under reduced motion (no intro to hide it).
- After: first visit, red sheet entry: no raster compiles, three 6ms compositor compiles, worst frame 18 to 20ms. Returning visit (Chrome keeps shaders on disk): 9 cache loads, 3ms, no slow frames. Full profiles (`redfix-*`, `services-*`): desktop p95 16.8ms everywhere, 0 long frames; phone at CPU x4 p95 16.8ms, 0 to 2 long frames per run, which move between runs.
- Machine load matters: with the other session rendering in Chrome, the phone runs swung from 3 to 22 slow frames in the same stretch. Compare runs made back to back, and repeat before believing a regression.

## Traps met
- Grid `1fr` tracks grow to the unfitted text / 1440px screenshots before fit.js runs -> the phone layout viewport went 1017px wide. Every grid that holds fitted type or plates uses minmax(0, 1fr).
- Element screenshots (puppeteer) hang on the live canvas; use page.screenshot with clip + captureBeyondViewport:false (tools/stills.mjs).
- Chrome ships without Albanian month/day names: albaniaNow() sets them by hand.
- WebGL draws above the DOM (fixed canvas, z 30): anything that must sit on top of a plate is drawn in the plate shader (callout rings and rules); proof notes carry z-index 35; the next case sheet clips the plates and the brayer by scissor.
- A `data:` URL inside a CSS custom property is re-parsed on every style recalc that touches it. Big generated textures go in as `blob:` URLs.
- three.js compiles a separate program for a render target and for the screen. Warming a pass against the screen still left a 45ms compile on the first stir; warm it with the render target it really draws into set.
- The frame skip needs every visual input in its dirty check. The roller's show/hide was missing at first. Switching to PROOF without scrolling hides the roller but moves nothing, so the brayer stayed drawn. The check now includes `roller.visible !== lastRV`, and a proof switch forces two redraws.
- A first-visit hitch with no main-thread work in it (long frame, render 3ms, no script) is the GPU process: look for `shader_compile` in the trace. Rounded clip-paths, exact circles with rings or blurred shadows, and new combinations of features in one tile each need their own Skia program.
- `.sort` is the 404's pied type. The languages' case uses `.typecase*`, and DESIGN.md's "type-case tiles" is the language-switch effect, a third thing.
- The ruflo-core plugin's after-Bash hook re-runs the text of Bash commands through cmd.exe (via an npx shim with shell:true), splitting at `&&`. It emptied tools/redsheet.mjs after a command that ran `sed -i` on it, and left stray files named like `name.html;` in LC/. Run commands here with the PowerShell tool, which that hook does not watch.
- Cross-document view transitions (the sheet feed between pages) were aborted at random with "InvalidStateError ... ViewTransition opt-in disabled": the new page sometimes revealed before its external stylesheet's `@view-transition` rule counted. The opt-in is now also written inline in partials/head.html; since then every page-to-page move transitions.
- Another Claude session works in this folder too (print, brand, the logo in partials/defs.html and chrome.html, and a block at the very end of style.css). Re-read shared files before editing, use targeted edits, and tell each other before touching the other's files.
- A PowerShell hook refuses any command that mixes Remove-Item with a forward slash anywhere in it; keep deletions in their own command with backslash paths.
